# GLM Coding Bot - 设计规格文档

## 概述

这是一个用于抓取 bigmodel.cn/glm-coding 购买接口的项目，支持多用户使用，并具备被封后快速复活的能力。

## 功能需求

- **库存监控**：实时监控商品库存状态
- **自动抢购**：检测到有货时自动执行购买流程
- **通知服务**：库存变化时通知用户
- **代理接口**：提供反封锁的代理访问能力
- **多用户支持**：混合模式（公共资源池 + 用户私有资源）

## 非功能需求

- **秒级复活**：系统被封后 10 秒内自动恢复
- **高可用**：多层健康检查，自动故障转移
- **反封锁**：IP 轮换、账号轮换、浏览器指纹伪装

## 架构设计

### 分层架构

系统分为 6 层：

```
┌─────────────────────────────────────────────────────────┐
│ 用户层                    Web UI  │  API Gateway         │
├─────────────────────────────────────────────────────────┤
│ 应用服务层     库存监控 │ 自动抢购 │ 通知服务 │ 用户管理 │
├─────────────────────────────────────────────────────────┤
│ 代理/浏览器层   代理池管理 │ 指纹轮换 │ 会话管理 │ 健康检查 │
├─────────────────────────────────────────────────────────┤
│ 资源池层      账号池 │ 代理IP池 │ Cookie池 │ 用户私有资源 │
├─────────────────────────────────────────────────────────┤
│ 数据持久化           PostgreSQL  │  Redis  │  文件存储    │
└─────────────────────────────────────────────────────────┘
```

### 核心组件说明

#### 1. 健康检查（秒级切换关键）

- **检查频率**：每 1-3 秒探测所有资源
- **故障检测**：HTTP 状态码、响应超时、内容校验
- **切换策略**：立即标记不可用，自动选择下一个可用资源
- **预热机制**：备用资源提前预热，切换无感知

#### 2. 指纹轮换

- 使用 `playwright` + `fingerprint-injector`
- 每个会话独立指纹：User-Agent、WebGL、Canvas、AudioContext
- 支持指纹模板保存/复用

#### 3. 代理池管理

- 支持 HTTP/HTTPS/SOCKS5 代理
- 自动检测可用性和延迟
- 动态切换，失败自动重试

#### 4. 会话管理

- 保存登录态 Cookie
- 会话复用和轮换
- 用户间会话隔离

## 数据持久化设计

### PostgreSQL

存储结构化数据：
- 用户账号信息
- 抢购记录/历史
- 代理IP列表
- 系统配置

### Redis

存储实时/缓存数据：
- 会话（Cookie、Token）
- 健康检查状态
- 热点数据缓存
- 任务队列

### 文件存储

- 状态快照（用于快速复活）
- 日志文件
- 浏览器指纹模板

## 快速复活机制

### 核心思想

将所有可变状态定期快照保存，新容器启动时自动加载。

### 快照策略

- **定时快照**：每 30 秒保存一次运行时状态
- **触发快照**：检测到异常时立即保存最后状态
- **快照内容**：Redis 数据、会话状态、资源池状态

### 恢复流程

```
检测异常 → 保存快照 → 容器重启 → 读取快照 → 恢复缓存 → 
恢复会话 → 预热资源 → 开始服务
```

**目标恢复时间**：< 10 秒

| 层级 | 技术 | 说明 |
|------|------|------|
| Web 框架 | FastAPI + Jinja2 | 异步高性能 |
| 浏览器自动化 | Playwright | 现代、快速 |
| 数据库 | PostgreSQL | 关系型数据 |
| 缓存 | Redis | 会话、状态、队列 |

| 反指纹 | fingerprint-injector, stealth-plugin | 指纹伪装 |

## 部署架构

使用 Docker Compose 编排：

- **web**：FastAPI 应用服务
- **worker**：Celery 异步任务
- **postgres**：数据库
- **redis**：缓存/消息队列
- **playwright**：浏览器自动化（可选单独容器）

### 复活策略

- Docker Compose `restart: always`
- 健康检查失败自动重启
- 启动时自动挂载数据卷，加载快照恢复

---

## 安全与注意事项

- 用户私有资源加密存储
- 操作日志完整记录
- 敏感信息（密码、Token）不写日志
- 合理设置请求频率，避免对目标站点造成压力
